## Deviations from design.md

1. **`test_placeholder.py` uses `-> None` return annotation.** The design shows
   `def test_ok(): assert True` without a return type. `mypy --strict` requires
   explicit return annotations on all functions; without `-> None` the lint step
   would fail with `Function is missing a return type annotation`. The fix is a
   one-character addition that is strictly more correct.

2. **`[dependency-groups]` instead of `[tool.uv.dev-dependencies]`.** When
   `uv add --dev` is run against uv 0.5+, it writes the dev group to the
   `[dependency-groups]` table (PEP 735), not `[project.optional-dependencies]`.
   This is the current uv idiom; `uv run` resolves it correctly and `uv sync --frozen`
   in CI will reproduce the same locked versions.

3. **Dev dependencies added: pytest, ruff, mypy.** The design lists them as tooling
   but does not show them in `pyproject.toml`. Without them in the lockfile,
   `uv run ruff` / `uv run mypy` / `uv run pytest` resolve from the system PATH
   rather than the project-pinned versions. Adding them ensures `uv sync --frozen`
   in CI installs the exact same versions as local.

## Known gaps

- `make test` requires a `.env` file with `POSTGRES_PASSWORD` set to start the db
  container. Without it, `docker compose up` exits 1 (Postgres refuses to start with
  a blank superuser password). The ONBOARDING.md `## Quick start` section covers
  `cp .env.example .env` before `make test`. CI is unaffected because it passes
  `POSTGRES_PASSWORD: test` directly in the workflow's `services:` block.
- `docs/adr/` already existed in the repo before this story; no `.gitkeep` was added
  there (it already contained `0001-python-lint-and-compose-baseline.md`).
